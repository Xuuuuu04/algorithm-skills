# Contest Protocol

## 必读参考
- **答案模板**: `references/answer-template.md` — 标准输出格式

## 双模式

### `lite`

用于比赛现场、代码修复、快速验证、用户只要求可提交代码的场景。

默认结构：
1. **思路**
2. **复杂度**
3. **仓颉实现**
4. **必要边界提示**

约束：
- 不强制展开形式化正确性证明
- 不强制列出完整风险项
- 证据引用只在出现非显然语法或 API 结论时启用

### `strict`

用于正式题解、教学、复盘、评测和审查场景。

按以下章节顺序输出，不得省略任何一章：

### §1 思路
- 用 1-3 句话描述核心算法思路
- 说明关键 insight（为什么选这个算法）
- 如果是 DP，明确: 状态定义 → 转移方程 → 初始化 → 答案位置
- 如果是图论，明确: 建图方式 → 算法 → 终止条件

### §2 复杂度
- **时间**: O(?) — 列出主操作 × 每次代价
- **空间**: O(?) — 列出主要数组大小
- 给关键变量定义 (如 n=节点数, m=边数, k=...)
- 论证为何不会退化

### §3 正确性要点
- 至少提供以下之一:
  - 循环不变量 + 初始/维持/终止论证
  - 数学归纳
  - 反证法
  - 贪心交换论证
- 禁止纯直觉描述

### §4 仓颉实现
```cangjie
// 完整可编译代码
// 必须包含所有 import 语句
// 必须包含 main() 入口
// 变量命名清晰有意义
```
**代码规范**:
- `import std.collection.*` — 需要集合时
- `import std.convert.*` — 需要 Int64.parse 时
- `import std.sort.*` — 需要排序时
- `import std.math.*` — 需要数学函数时
- `import std.overflow.*` — 需要溢出处理时
- I/O 用 `readln()` + `split(" ")` + `Int64.parse()`
- 输出用 `println()`

### §5 边界测试
至少 5 类，格式:
```
输入: [具体值]
期望: [结果]
验证: [通过/说明]
```
必测类型:
1. 最小输入 (n=0, n=1)
2. 最大输入 (n=max)
3. 全相同值
4. 负数/零
5. 退化结构 (链状树、完全图等)

### §6 风险项
至少 2 个，格式:
```
风险: [描述]
概率: [高/中/低]
规避: [策略]
```
常见风险:
- Int64 溢出 → 用 overflow 或减少中间乘积
- 数组越界 → 边界 check
- TLE → 检查复杂度常数
- HashMap 哈希冲突 → 改用 TreeMap
- 递归栈溢出 → 改迭代

### §7 证据引用
格式: `path | anchor | "quote"`
- path: 本地文档路径
- anchor: 标题锚点
- quote: 原文短引 (≤30 字)

至少 1 条语法引用 + 1 条 API 引用。

## 交付前自检清单
- [ ] lite 或 strict 模式已明确
- [ ] strict 模式下 7 章节全部存在
- [ ] 代码含所有 import
- [ ] 代码有 main() 入口
- [ ] 复杂度与实际代码一致
- [ ] 无未定义符号
- [ ] strict 模式下证据引用可定位
- [ ] strict 模式下边界用例 ≥ 5 个
